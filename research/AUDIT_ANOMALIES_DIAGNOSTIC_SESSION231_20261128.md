# Anomalies supplémentaires du diagnostic — SESSION 231
Source figée : 4b465406cca3a3a619b0396bc8ca85c3af4c9dc0. Inspection directe des sources et des traductions. Aucun changement de programme ni de DLL. Pas de test matériel.
1. **Conclusion NORMAL malgré des contrôles non évalués.** diagnosticpanel.cpp:246-265, 317-326, 412-418. Le résultat global dépend uniquement des compteurs issues et warnings. Un DTC de statut Missing/Unverified sans bit reconnu n'ajoute pas d'incertitude au résultat global ; les corrections non qualifiées non plus. Si les autres contrôles ne déclenchent aucune alerte, NORMAL est possible. Même KBHBG009 peut avoir un DTC2 non évalué et ce résultat global.
2. **Réutilisation d'une référence de diagnostic d'un autre calculateur.** diagnosticpanel.h:42-55 (Snapshot sans identifiant), diagnosticpanel.cpp:177-217 (reset uniquement m_naReference), 400-407 (comparaison m_reference), 438-442 (capture commune aux non-NA), 525-526 (rapport). Changer de calculateur non-NA ne réinitialise pas m_reference dans ces chemins et la comparaison n'exige aucune identité. Une référence MEMS 1.9 peut être utilisée avec un autre MEMS 1.9 ou une autre génération passant par rebuild générique.
3. **Interprétation automatique DTC2 sans qualification.** diagnosticpanel.cpp:246-247, 297,305 et mainwindow.cpp:1225,1319-1326. Hors profil NA ou DTC2 connu KBHBG009, le brut est pris comme masque de défaut ; bits 01,04,08 déclenchent TPS et lambda sans preuve de leur signification sur le firmware connecté. Exemple logique : un brut FF entraîne ces alertes même si le champ est non interprété ; pas de preuve que ce brut soit effectivement transmis par une référence particulière. Il faut un décodage par profil, pas effacer les alertes.
4. **Seuil de bobine appliqué au MEMS 1.9 sans qualification spécifique.** diagnosticpanel.cpp:328-359 : commentaire désigne MEMS 1.3/1.6, mais branche générique inclut les MEMS 1.9 et peut déclarer OK, surveillance ou anomalie au moyen de seuils 2–3,5 ms / >4 ms. Absence de contrôle de famille dans ce bloc. Les seuils ne sont pas démontrés faux sur 1.9 ; leur validation 1.9 n'est pas établie par ce code.
5. **Calcul de ralenti historique utilisé hors profil qualifié.** diagnosticpanel.cpp:363-390, 491-506 ; mems220_measurements.h:7-9. Pour les références autres que KBHBG009 dans la branche générique, le calcul 7D14-15 - 32768 - (idle_hot-35) sert à déclarer OK ou avertissement avec seuil ±15, sans qualification de la disposition et de l'échelle. Le code ne prouve pas que ce calcul est faux pour toutes les autres références.
6. **DTC2 KBHBG009 ne peut jamais atteindre le statut Decoded.** memsextendeddtc.h:54-67 : complete reste false pour group=2, y compris brut 00 ; diagnosticpanel.cpp:249 en déduit incompleteDtc2. Ce comportement peut être conservateur et justifié par la cartographie incomplète ; ce n'est pas une raison de prétendre que le DTC2 est intégralement validé. Le test memsextendeddtc_test.cpp:34 vérifie seulement le masque des défauts, pas le statut.
7. **Rapport exporté incomplet pour les états étendus MEMS 1.9.** diagnosticpanel.cpp:366-381 affiche dix lignes, dont D/N, climatisation, coupure allumage, demande ventilateurs. buildReport():495-504 n'exporte que six clés (29031,29026,29025,29024,2972001,29033). Les quatre états étendus ne sont pas exportés par cette boucle.
La traduction FR et EN du calcul historique (clé 6897) contient bien le signe moins. Le commentaire anglais du code ligne 388 affiche un plus mais il n'est pas affiché à l'utilisateur : ne pas le présenter comme erreur de calcul ou d'interface.
Conclusion : anomalies logiques démontrées par lecture, et qualifications techniques manquantes distinctes. Audit ciblé, pas audit complet de toutes les générations ni test de véhicule.
